How I keep two apps green on every push

Manideep Daram, 2026-11-15 — Full Stack Developer, Hyderabad

TL;DR. TaskFlow and DocVault are not demos. TaskFlow runs 44 tests on every push to GitHub; DocVault runs 15. Same permissions matrix reads in two places: the UI and the API. Hidden buttons are fine, but they are not security — refused requests are.

The discipline is the same everywhere

TaskFlow: routes → services → repositories, PostgreSQL schema, JWT with bcrypt, roles enforced once in the service layer, refusal returned by the API. DocVault: a single 5-permission matrix read by <RoleGate> and by every route handler. Same shape. Nothing fancy. Just refusing instead of hiding.

What the tests actually cover

  • Permissions matrix coverage — can(role, permission) for the full role × permission grid, plus fail-closed behavior for an unknown role.
  • Route-layer authorization — every protected route refuses the wrong role with a 4xx, not a silent redirect.
  • Form validation — required fields, error states, and empty states render properly.
  • Rendering — role-specific rendering of the same page confirmed with react-dom/server.

Role Based Access Control — one matrix, two places

The matrix is five permissions over three roles. viewer: ['doc:read']. reviewer: ['doc:read','doc:review','doc:upload']. admin gets all five. The UI (<RoleGate>) reads it to decide what to render. The API route handlers read it to decide what to allow. There is exactly one file that defines "who can do what," so permission never drifts out of sync between what the user is shown and what the server enforces.

Why this matters even for small projects

A reviewer or an ATS will ask: "how do you handle access control?" The answer below is much stronger than "I have login." In DocVault, a viewer literally cannot create a document, and you can watch the route refuse. In TaskFlow, a member cannot delete projects, and the service layer decides that before the API is asked. That distinction is the one that distinguishes a full stack developer from a front-end coder.
