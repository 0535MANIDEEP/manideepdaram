The RBAC pattern: one matrix, two places

Manideep Daram, 2026-11-15 — Full Stack Developer, Hyderabad

TL;DR. Role Based Access Control means permission decisions are made by the server, not by the frontend. One matrix. Read by the UI to render only what you can click. Read by the API to refuse what you shouldn't do. If only one of those reads, the app leaks.

The matrix in two lines

export type Permission = 'doc:read' | 'doc:create' | 'doc:upload' | 'doc:review' | 'doc:delete';

const MATRIX: Record<Role, readonly Permission[]> = {
  viewer:   ['doc:read'],
  reviewer: ['doc:read', 'doc:review', 'doc:upload'],
  admin:    ['doc:read', 'doc:create', 'doc:upload', 'doc:review', 'doc:delete'],
};

Why hiding instead of refusing is not enough

Because an attacker can call the API directly. A hidden button tells the user "you shouldn't do this." A refused request tells the server a firm boundary. When RBAC is correctly enforced server-side, the UI's button hide is a UX convenience, and the server's refusal is a security guarantee.

What the three roles see in DocVault

  • Viewer — can log in, see documents, preview. The review/upload/create buttons do not render. Calling the API for any of those returns 403.
  • Reviewer — can upload and review. Cannot create or delete.
  • Admin — full set, including delete.

What TaskFlow does with the same idea

Two roles: admin and member. The service layer reads the role from the database on each request (not from the JWT), then decides whether the requested action is allowed. JWT alone is a bearer credential — role claims in a token go stale the moment some token-expired actor reassigns a user. Reading from the DB means permission changes take effect immediately.

FAQ

Is your permission check client-side only? No — both live apps enforce it on the server too. Hidden controls in the UI are just conveniences. The refusal you actually get is from the API.

What about JWT? JWT identifies who you are. The server decides what you can do by looking up the current role in the DB. Token alone does not authorize; the role is authoritative.
